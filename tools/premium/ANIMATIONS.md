# Анимации для премиум-сайтов (навык из ролика «5 сайтов не как у всех»)

Инструменты из ролика: **Anime.js** (анимации), **Motion** (переходы, отклик на курсор), Kokonut UI (идеи блоков, React),
Bklit UI (анимированные графики), Manus (агент — нам не нужен). Для наших страниц берём Anime.js с cdnjs:
`https://cdnjs.cloudflare.com/ajax/libs/animejs/3.2.2/anime.min.js`.
Для шаблона (сайты-приложения, работают без сети) внешнюю библиотеку не подключаем — то же делать встроенным Web Animations API.

Правило: 1–2 ярких момента, а не «всё прыгает». Всегда уважать `prefers-reduced-motion`.

Рабочий пример — `extra/vlghair/index.html` (выложен, проверен):
1. Первый экран — одна последовательность (`anime.timeline`): фото в арках поднимаются (`translateY: [80,0]`, `scale: [.92,1]`,
   `anime.stagger(140, {from: 'center'})`), затем текст и кнопки.
2. Рейтинг и число отзывов считаются от нуля: элементы с `data-count="5.0"` / `data-count="401"`.
3. Блоки проявляются при прокрутке: контейнеру ставим `data-reveal`, его дети появляются по очереди (IntersectionObserver, один раз).
4. При смене вкладки прайса строки появляются по очереди (`#menu li`, stagger 35 мс).
5. Главная кнопка тянется к курсору (только мышь, `pointer: fine`) и пружинит назад (`easeOutElastic(1, .5)`).

Защита от «пустого экрана»: в `<head>` сразу ставим класс `anim` на `<html>` (скрывает анимируемые элементы)
и снимаем его через 2,5 с в любом случае — если CDN не загрузился, страница всё равно видна.

Проверка: снимки на 0,3 / 0,5 / 0,7 / 1,2 / 2,6 с после загрузки и после прокрутки (Playwright), смотреть,
что цифры досчитали до конца, а блоки стали видимыми (opacity 1), и что нет ошибок на странице.
